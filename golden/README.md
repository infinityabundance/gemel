# Gemel Golden Fixtures

This directory contains the **executable golden vectors** that bind the Gemel
specification to its implementation (OBJECT_MODEL.md §11–§12).

## Contents

```text
golden/
├── manifest.json        ; machine-readable vector registry (schema gemel.golden.v1)
└── vectors/
    ├── <name>.gce.hex   ; canonical envelope bytes, lowercase hex
    └── <name>.id        ; textual object identity
```

## What is pinned

- The exact canonical bytes (`GCE`) of representative objects for **every family**,
  including: empty and binary blobs; trees with files, executables, symlinks, and
  nesting; chained objects (trajectory/case/residual/checkpoint/config with
  `previous`); the acceptance-demo-shaped change (claims + evidence + residuals);
  multi-parent changes; agent runs with context manifests; oracle evidence with
  reproduction records; and an extension-field object proving lossless retention.
- The BLAKE3-256 identity of each vector.
- Cross-references between vectors (a change referencing a claim, evidence, or state
  references that vector's **pinned identity**).

## Verification

`cargo test` verifies:

1. `decode(encode(object)) == bytes` and `encode(decode(bytes)) == bytes` for every
   vector (byte-exact, including extension retention);
2. computed identities equal the pinned `.id` files;
3. envelope family/schemever match the manifest;
4. cross-references resolve to pinned identities;
5. the negative fixture catalog (fail-closed behavior) rejects as specified.

## Regeneration policy

Golden vectors are regenerated **only** as part of a deliberate protocol change
(an `encver` or `schemever` bump), under review, and committed together with the
change that required them (OBJECT_MODEL.md §10.4).

`golden-gen` refuses to run when the working tree has uncommitted golden changes unless
`--force` is passed and the operator confirms the protocol intent.

## Provenance

Vectors are generated by `src/bin/golden_gen.rs` from the fixture
definitions in `src/golden/mod.rs`. They are deterministic: the
same tool and fixture definitions produce the same bytes and identities on every
machine.
